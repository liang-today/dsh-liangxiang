# 2.0.1 客户端请求与恢复验证

本批源码为 `2.0.1-alpha.3`，未发布、未部署。保留此前市场行情恢复与源码图片兜底；正式客户端及后台、日常Profile和正式账本未改动。

## 请求预算

`src/shared/request-budget.ts` 是两层预算的单一来源：Host每次请求仍为6秒，普通读取最多重试一次，中间等待300毫秒，合计最多12.3秒。浏览器JSON请求为15.3秒，覆盖上述完整读取并留出3秒本机传输／解析裕量；读取正文仍受同一个计时器约束。3秒是保守工程余量，并非真实延迟分布测出的最优值；15.3秒属于约15秒的等待上限，正常响应立即返回，不会主动等待此期限。

该上限只约束共享浏览器JSON请求，不代表全项目所有超时；本机缓存读取也复用此上限，SSE另用自己的建连、闲置和重连策略。

这不是整个写入链路的完成保证：上香或调整仓位可能先等待既有凝香结算。超时不能解释为未成交或自动退款；未确认仓位保存原请求号，自动恢复只读，用户显式核对时才重发同一意图。分页K线逐页使用请求预算，不把全天数据遍历压成一个15.3秒总期限。

## 恢复与信息保持

- 共享浏览器请求边界将原生AbortError／超时和网络中断转为中文；关闭窗口时取消请求与计时器，迟到回包不复活窗口。
- 主面板的原生EventSource若收到503后直接CLOSED，单次错误即转入原有有界重连；连续断流按1、2、4秒逐步退避，最长30秒，只有有效实时帧才重置间隔。普通可恢复错误仍保留原阈值，旧流回调按代际丢弃。
- 梁股保持已有1至30秒有界重连；K线读取失败后5秒补读，成功即停止额外补读。关闭、换身份或换案会取消旧任务。
- 不修改Host行情cadence、正常SSE频率、分钟粒度、分页范围或图表信息量。原画、动效及原客户端体积上限保留。
- 迟到的旧身份／旧案仓位响应不能覆盖当前状态或误清待确认意图；换案后显式核对同一请求仍能结束其不确定状态。

## 本机412核实

本轮重新只读采样确认：仍运行的Web Profile安装梁相1.2.0，持续收到 `412 wallet_upgrade_required`；Desktop安装2.0.0，在线且没有该错误。两者不能混为同一个客户端的网络故障。

这项响应保护已启用累计钱包的身份，防止旧日账请求覆盖累计余额、冻结或结算；没有修改或绕过保护。未关闭、升级、重启或清理日常Web／Desktop Profile。若继续使用旧Web，应在后续明确操作中单独升级该Profile，并保留身份与数据；不需要重建钱包。

## Web与Desktop共存边界

DSH的Profile用于隔离安装和配置，不能替代DSH_HOME数据根隔离。同一数据根默认共用梁相身份和用量水位；两个独立Host的JSON内存副本缺少跨进程写入协调，存在本地文件覆盖风险，尚无本轮实际丢失证据。服务器412只能保护累计钱包，不提供本机写入互斥，也不按Desktop或Web名称决定权限。

优先保留正常Desktop。测试Web使用独立数据根和原测试身份，不能清理、重建或导入Desktop账本；两种入口同时使用独立数据根时，身份／钱包也独立，不应声称自动合并。日常同数据根双Host的完整并发协调另行设计验证，不能仅通过日志标识宣称已解决。

本批新增本地日志来源标识：插件版本、经官方入口核实的Web／Desktop类别（无法确认则Host）、Profile摘要和进程标记。不输出Profile名称、路径或钱包身份，不向后台上传。已安装旧版不会因另一入口升级而自动获得这些标签。
