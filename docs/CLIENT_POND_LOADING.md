# 客户端水景、等待提示与测试控制

源码候选 `2.0.1-alpha.5`，未发布。本批按用户明确要求只更新本机3999插件与本地网络测试器；香港隔离后台保持上一轮alpha.4-u1／schema15，不部署、不重启、不改配置或数据。正式服务与正式账本不参与。本轮是客户端与本机Host验收，不冒充整套前后端同候选发布验收。

## 请求活动水景

- 原人物两侧上浮烟线替换为水面两处轻涟漪、环底短弧呼吸光；装饰取现有真实streamingActive，不估算Token或香火。
- 涟漪放在既有tide容器内，沿原waterDrop变化；零水不显示，不改mainPondGeometry、香火环fill、人物浮动或任何记账公式。
- 复用已有静态／可见性门；隐藏、离屏及遮罩时暂停／移除，减少动态时保留低亮静止表现。活动不进入鱼景hook依赖，游鱼、水草、两次吐泡泡及水面破泡保留原时序与清理。

## 梁股打开等待

每次打开都新建会话并先读当前权威行情，正常快响应立即显示；网络建连、测试桥接和重试会带来不定等待，不存在固定等待动画。历史页与K线分页不阻挡首个行情状态渲染。

原逻辑第二次打开不重播首次捕鱼，但把仍然必需的读取文字放进了仅辅助阅读区域，于是正文像空白。本批每次等待均显示原读取提示，首次捕捞动画仍只播放一次；不新增余额缓存，不按旧钱包提前开放交易，也不降低刷新频率。

本机Host另修复同类恢复标记：有效、同身份／代际／案号的读取证明网络已恢复时，即使其旧时间或旧钱包不能覆盖确认状态，也清除transport失败并恢复本机SSE；无效、错案、旧代际仍不能伪恢复。远程Backend不变。

实际3999断网复测还发现历史回执失败晚到、恢复后提示残留的问题。本批把历史读取错误与交易／网络错误分开，以单个5秒计时器只读重试失败的原页；旧代际不覆盖新状态，成功只清自身提示，原订单与待确认请求不受影响。重连、身份／场次变更和关闭时清理旧读与重试；正常行情刷新频率不变。

## 本地测试开关

`scripts/dev-network-gate.mjs`仅监听回环，连接既有本地测试隧道，控制页继续使用原端口。它区分“出口已放通”和“DSH已连通”，只读取本机缓存状态，不额外请求云端行情或改变插件重试节奏。

快速操作通过命令序号及页面代际过滤旧请求／旧状态，以最后一次意图为准；按钮立即反馈，状态约300ms校准。恢复仍需要插件的真实重试与有效回复，不能把按下开关当成已经联网。会话凭据仅在内存中用于该回环Host，不出现在控制页或日志中。
