# 凝香速度核对

核对日期：2026-11-03。范围为源码与隔离回归；不将推测当作受影响用户的实测结论。

## 已确认

- v0.8.3-beta、v1.0.0、v1.1.6、v1.2.0 与当前候选均采用 Pro ×1、Flash / 其他 / 未知 ×0.5；默认一炷分别需要 50,000 / 100,000 原始 Token。本轮没有提高门槛。
- 输入包含未缓存、缓存读、缓存写，输出全量计入，reasoning 不重复加；每日 10 炷保留。模型选择和 Token 消耗量会影响同样使用时长下的凝香量。
- v1.1.6 观察流式累计投影并取单调高水位；v1.2.0 起只结算每次请求最终 provider usage。请求尚未结束时，不再提前凝香；结束后按最终用量入账，而非每个流式样本累加。
- 旧高水位不能撤回偏高的临时用量，也可能把历史用量增长按会话后来的模型折算。当前逐请求路由与最终用量修正了这两种偏差；这可能减少旧版曾多记的香火，但不是普遍变慢的证据。
- DSH 0.2 使用内嵌 stream 的 `assistant/message` / `assistant/attempt`。当前解析覆盖最终 usage、失败/取消、重试和缓存桶；仅支持旧 chunk 的适配器会漏记。不得把旧插件与任意新 DSH 的组合当成已验证兼容。
- 新版定时上香会消耗余额；判断凝香速度应比较同一业务日“今日凝香”的增量，而不是只比较环上剩余量。
- 本轮浏览器回归发现并修复：初始化时误用浏览器 UTC 占位日，会清掉与 Host 业务日不同的本机投香日统计。现等真实 Host 帧再读/日切；这是此身香火与梁小号展示问题，不改服务器凝香或余额。

## 回归依据

固定 DSH 0.2.1-rc.2：`tests/settled-usage.spec.ts` 直接使用原生 Session 与 TokenMeter，核对最终下调、四桶、混合路由、重试、迁移、重启、模式切换和重放；`tests/domain-incense-weight.spec.ts` 核对规则。源码入口为 `src/compat/dsh/settled-usage.ts`、`src/host/usage-ledger.ts` 与 `src/domain/incense-weight.ts`。适配证据见 `COMPATIBILITY.md`。

## 当前 DeepSeek 实时流边界

钉住的 DSH 0.2.1-rc.2 / `687f282e86` 确有 `agent/assistant-stream` 实时帧：
`@deepseek-ai/dsh-agent-loop/lib/index.js` 的 `AssistantStreamAttempt.push` 逐块发布，
`ReactLoopAgent` 在请求开始/结束发布生命周期帧。
但 `@deepseek-ai/dsh-llm-deepseek/lib/index.js` 的 `translate` 仅在 `message_stop` 处 yield
一次 `type: 'usage'`；此前的原始 provider usage 虽被内部更新，却未通过适配器输出。
同版 `@deepseek-ai/dsh-token-meter/lib/index.js` 的 `usageOf` 也只读取最终持久事件。
以上从本仓锁定 npm 包的编译实现与声明核验；不修改 DSH。

因此，仅恢复旧累计投影算法，不能让当前 DeepSeek 路由在回复途中提供连续的真实
Token 数。可单独表现“请求正在进行”，但不得按字符数、时间、Context Occupancy
或匀速动画虚构用量，也不得将临时样本提前变为可消费香火。若其他适配器实际提供
多次 usage，预览可跟随真实样本，最终到账仍须防下调、多计和重放。

## 尚不能断言

没有受影响用户的插件实装版本、DSH 版本、请求路由及单次最终用量对照，不能确认每个反馈都是正常变化，也不能宣称没有漏计。最小复核不需要对话正文或 API Key：记录同一已完成请求的模型路由、输入/输出及缓存数字，对照今日凝香和下一炷前后变化；同时注明是否刚升级、断网或开启定时上香。

首次接入或会话格式迁移会建立历史基线，避免重复铸香；边界上未结算的旧请求可能不补记。已记账香火不追溯扣减，也不凭估算补香。

## 限流与上线状态

当前候选默认投票额度每分钟恢复 500 炷，桶容量和单次请求各最多 500；定时上香仍为 10 分钟。这三项都不改变凝香公式。

线上原为正式 `1.2.0 / 1.2.0-u1`（`8d5e27c`），代码默认 50 炷/分钟，无环境覆盖。
已从该正式版分出独立后台维护分支，部署 `1.2.0-u2 / 2f2d6e3`：默认恢复 500 炷/分钟，
桶容量和单次上限各为 500。npm、客户端和官网仍为正式 1.2.0，没有发布本轮候选。
现有客户端直接受益；旧客户端限流提示的旧数字须等后续客户端更新，不能由后台改写本机文案。

部署前后一致性备份保留；schema 均为 10，quick_check=ok、外键异常 0。
首次安装因临时工作树根目录的 0700 权限被复制到服务目录，出现 CHDIR 失败与短暂 502；
脚本现于复制后固定恢复 0750，二次标准部署、内外 health、history 和 VERSION 检查通过。
回滚源为正式 `v1.2.0 / 8d5e27c` 与部署前备份；不重置身份、余额或投票，不做数据回滚。
线上验收只读，没有登记生产测试香客、赠送测试香火或提交测试投票。
