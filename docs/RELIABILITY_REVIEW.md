# 可靠性加固与验证边界

当前候选：2.0.1-alpha.9。基线：2.0.0及前批恢复候选。
只提交个人fork源码，不部署、不发布，不操作正式账本或现有手测Profile。

## 已处理的边界

| 范围 | 实现与约束 | 验证入口 |
|---|---|---|
| HTTP正文 | 原始字节限长、跨块UTF-8正确解码；Host/Backend共用实现 | reliability-boundaries |
| 行情版本 | 快照发布序号与市场计数版本分开比较；即时公共快照仍可更新报价；旧钱包不得倒退持仓 | host-market、host-market-recovery、recovery-route |
| 坏实时帧 | 短暂坏帧隔离，持续错误显式离线并自动重连；保留最后正确数据 | live-store、backend-client、event-stream |
| 并发领取 | 等待在途任务后再次检查，单一领取请求占有在途状态 | host-market |
| 身份与生命周期 | 写入等待前后检查身份；初始化中的服务也受卸载管理；身份创建单飞且先持久化 | host-market、host-apply、storage |
| 跨钥匙恢复 | 设备指纹不是归属证明；保留旧钥匙，不自动删除别人的身份；资产/冻结保护不变 | identity-recovery、host-backend、starter-incense |
| 离线赠香 | 重启校验计入原有赠香，已消费部分不退回 | host-service |
| 定时上香 | 同日换案不能吞掉新案收尾；先确认旧意图，同一意图仍用原请求号；未知历史批量不猜实际接受量 | day-end |
| 用量游标 | 缺格式保留已知格式，真正迁移仍重基线；尾数随完整累计记录合并，不能逐字段取最大 | settled-usage、reliability-boundaries |
| 演示活动 | 丢失结束事件只让动效有界失活；绝不据此结算或估算香火 | streaming-activity |
| 本地观察走势 | 缺口不覆盖真实计数；保留换案断线；路径校验；跨日坏盘待写重试、日志节流、关闭日期缓存 | domain-bars、host-bars |
| 日志 | 追加先读长度，超限仅读尾部并保留余量，不每行全读重写 | host-file-log |
| SQLite升级 | 获得写锁后再读版本，防并发重复执行旧迁移 | starter-incense、market-minute-data、wallet-activation |
| 档案重同步 | schema16添加reset_version；清历史递增版本；旧游标得到full响应，重启后仍可替换旧缓存 | backend-history |
| 档案损坏 | 损坏标题明确显示不可用，保留原始计数和数据库记录；不能伪造正常案名或静默删档 | backend-history |
| 档案统计 | 未知香客数与真零区分；行级版本防回退；损坏定时设置隔离，身份和游标保留 | history-v1、storage |
| 参数与协议 | 当前态日期/案例/快照一致；保留历史投票重放语义；投票最小意图白名单；接收字符串有宽松兼容上限 | backend-client、reliability-boundaries |
| 旧市场读者 | 真实分钟数据可聚合成五分钟；原五分钟数据优先且不拆分；累计夯拉取末值，成交量求和 | market-minute-data |
| 后台资源 | 初始化异常关库；有界等待活动请求结束再关库；队列查重与写入同事务 | backend、operator、rehearsal tests |
| 券与读放大 | 公开库存只读；公开冷读独立限流，不降行情频率；批量生成/自动库存单批上限1000 | admission、backend-http、reliability-boundaries |
| 限流诊断 | 非法内部数量拒绝；容量耗尽与冷却区分，保留失败关闭；健康读只公开容量计数 | vote-rate-limit、operator-identity |
| 本机统计 | 支持Web Locks的浏览器串行更新装饰统计，跨标签页事件刷新；不支持时保留原降级，不影响权威钱包 | local stats、browser smoke |
| 时钟与配置 | NTP以当次请求中点计算偏差，只告警；非法时区启动明确失败；坏演练时钟仍停交易 | config、rehearsal |

## 复核后保留的保护

- live最终请求分配给已确认的业务日，不能以本机事件时间偏差把它丢掉；catchup继续使用日期过滤和首次观察游标。
- 未知实时梁子策略的兼容展示保留，封存档案继续严格；不借加固重解释旧历史。
- 累计钱包、离线日账、数据库事务责任不同，不强行合成一个记账fold；展示继续复用纯领域计算。
- 粗粒度的gap表示整槽无样本，部分观测仍保留真实K线及原始gaps；不把真实数据整根隐藏。
- unsigned仅显式回环测试使用，部署模板固定关闭；现有默认验签与演练环境拒绝规则保持。
- 云端恢复已有指数退避与独立抖动，保留而不重复增加轮询。
- 演练时钟损坏必须停止，不能回退现实时间或继续接受冻结时钟下的交易。
- 上香预算容量不足已返回429，不会修改钱包为0；保留相关HTTP回归，不能按报告描述重写钱包。

## 长期数据保留

幂等回执、设备/日期赠香去重和会话结算游标不是可随意过期的缓存。
删除它们可能把旧请求重新评价或把旧会话重新凝香。默认不自动清理。
后台status只读显示日账、回执、赠香墓碑及队列行数；Host可读游标/日账数量，超大游标集合给本机诊断。
离线已接受案例使用集合索引，避免每次投票扫描所有历史回执。
需要压缩或归档时，先证明重试、防重放和旧版兼容语义，再在副本演练；不按天数直接删除。

## 梁标上下浮动

从恢复浮动的历史实现、正式2.0.0到当前候选，周期与幅度均未改动。
周期由下一炷进度线性决定：0为4800ms，50%为2950ms，100%为1100ms；中点上移7px。
可用余额、梁位、水位都不改变周期。减少动态偏好停止位移。
此次增加周期边界回归，不调整快慢或删除动效。

## 此前漏测的原因及改进

1. 常规HTTP测试一次发送完整字符串，没有把中文字符拆到TCP块边界；现在同时测原始字节与真实签名HTTP。
2. 内存存储通常立即完成，未模拟写入未完成时的并发解析、卸载和换身份；现在延迟写入并验证所有权。
3. 测试里的快照与行情序号经常同步增长，掩盖两套计数器的区别；现在特意用100与2的反例。
4. 赠香、重启、离线和同日换案分别测过，但组合覆盖不足；现在用花完/部分花费重启和旧意图收尾组合。
5. 既有测试通过被概括成过宽的整体结论。通过只能证明所列场景，不能覆盖全部操作系统、断电、第三方Profile损坏或未来协议。
6. 静态审查建议也可能忽略调用链中的保护。每条先核验当前版本、触发入口、既有测试与产品契约，再决定修复或保留。

后续修改需按触点选择失败矩阵：分块/超限、乱序/错域版本、延迟写入/卸载、跨日/同日换案、重启/丢回执、坏记录/恢复、旧新版本交互。
新增回归要能复现真实边界，不以测试数量或界面演示代替服务链路证明。
