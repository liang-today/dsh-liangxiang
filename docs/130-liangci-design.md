# 130 — 梁祠（日梁 / 周梁 / 月梁）设计方案

> 状态：设计提案，供 Cursor 后续实施；本文不代表功能已经实现。
>
> 本方案延续 `AGENTS.md` 的二元投票、梁位、梁子五态、业务日、快照一致性与软信任边界。
> 梁祠只读，不改变今日梁案、个人香火、投票资格或权威账本。

## 1. 产品目标

梁祠是梁标的历史日历：以月历为主视图，用三种时间层级组织全局梁位。

- **日梁**：一个业务日一个日历图标。
- **周梁**：周一至周日七个日梁的汇总，显示在对应七天右侧。
- **月梁**：一个自然月全部日梁的汇总，显示在月份标题区。
- **今日**：尚未结束，不显示今日梁位或今日梁子终态，只显示专用的 **今日进行中** 图标。

梁祠的核心原则是：**只有已经结束的业务日才能进入历史计算。**

## 2. 冻结与临时结果

### 2.1 日梁

- 今日格固定显示 `今日进行中` 图标，不用实时今日梁位生成日梁图标。
- 今日不参与本周暂梁、本月暂梁计算。
- 到下一业务日开始时，服务器封存昨日的最终夯票、拉票与日梁元数据。
- 封存后的日梁不可被今日快照或浏览器时钟改写。
- 同一业务日若因运营归档、重开而存在多个梁案，当日日梁合并该业务日所有已关闭梁案的 accepted 夯/拉票数。

### 2.2 当前周梁

- 周期固定为服务器业务时区下的 **周一至周日**。
- 本周尚未结束时，显示 `本周暂梁`。
- 本周暂梁只使用本周一至昨天的已封存日梁；不包含今日。
- 暂梁不写永久档案，可由一次性历史数据在 Host / Client 侧即时派生。
- 下一周首个业务日到来时，上周结果已经固定，服务器生成且只生成一次永久周梁档案。
- 若今天是周一，本周没有任何已结束日期，显示 `本周待积`，梁位为 `--`，不可显示假 50%。

### 2.3 当前月梁

- 月周期按服务器业务时区下的自然月计算。
- 本月尚未结束时，显示 `本月暂梁`。
- 本月暂梁只使用本月 1 日至昨天的已封存日梁；不包含今日。
- 暂梁不写永久档案，可由一次性历史数据在 Host / Client 侧即时派生。
- 下一月首个业务日到来时，上月结果已经固定，服务器生成且只生成一次永久月梁档案。
- 若今天是当月 1 日，本月没有任何已结束日期，显示 `本月待积`，梁位为 `--`。

### 2.4 结果状态矩阵

| 对象 | 数据范围 | 展示状态 | 是否永久入档 |
|---|---|---|---|
| 今日 | 当前业务日 | 今日进行中 | 否 |
| 昨日及更早的日梁 | 完整业务日 | 已封存 | 是 |
| 当前周 | 本周一至昨天 | 本周暂梁 / 本周待积 | 否 |
| 已结束周 | 完整周一至周日 | 已封存周梁 | 是 |
| 当前月 | 本月 1 日至昨天 | 本月暂梁 / 本月待积 | 否 |
| 已结束月 | 完整自然月 | 已封存月梁 | 是 |

## 3. 聚合口径

主梁位采用“先汇总票数，再计算比例”，即按香火数加权：

```text
period_up_votes   = sum(day.up_votes)
period_down_votes = sum(day.down_votes)
period_total      = period_up_votes + period_down_votes

if period_total == 0:
    up_ratio = null
    down_ratio = null
    liangzi_state = WAITING
else:
    up_ratio = period_up_votes / period_total
    down_ratio = period_down_votes / period_total
    liangzi_state = liangziPolicy(up_ratio)
```

这等价于以每日总香火为权重，对日梁位做加权平均，并保持 `1 accepted vote = 1 incense` 的产品语义。

规则：

- 不平均 `梁工 / 梁总 / 梁神 / 梁圣 / 梁祖` 枚举。
- 零票日是合法的 `待开梁` 日梁；它在周期聚合中的票数权重自然为零。
- 功能上线前没有数据的日期显示 `无存档`，不可冒充零票日。
- 未来日期留空。
- 周梁/月梁的梁位、称呼与梁子图像必须来自同一组周期计数和同一聚合版本。
- 梁位显示继续截断而非四舍五入；详细卡保留 6 位小数。

若未来需要“典型的一天”视角，可在详情中增加次要指标 `有票日日均梁位`；它不得驱动主周梁/月梁图标或称呼。

## 4. 日历信息架构

梁祠使用独立大浮层或侧抽屉，不把 312px 的今日梁案面板扩展成月历。

```text
┌────────────────────────── 梁祠 ──────────────────────────┐
│ 〈上月               2026 年 8 月                 下月〉 │
│                                  本月暂梁 · 截至昨日     │
│ 一    二    三    四    五    六    日       周梁         │
│ 日梁  日梁  日梁  日梁  日梁  日梁  日梁     已封存周梁   │
│ 日梁  日梁  日梁  日梁  日梁  今日进行中     本周暂梁     │
└──────────────────────────────────────────────────────────┘
```

### 4.1 图标语言

- **日梁**：单页日历框 + 日期 + 小型梁子头像。
- **今日进行中**：未盖印的今日历页，明确写 `今日进行中`；它不是 `WAITING / 待开梁`，也不绑定实时今日梁子状态。
- **周梁**：七格日历册或横向卷轴框 + 周梁子头像。
- **月梁**：完整月历牌匾 + 较大的月梁子头像。
- **暂梁**：虚线或未盖印边框，并带 `暂` 标记和 `截至昨日` 文案。
- **永久档案**：实线封边或盖印视觉，不再出现 `暂` 标记。

日、周、月通过不同的“时间容器”区分；容器内梁子仍只使用 `待开梁` 和现有五态，不创造新档位。

### 4.2 当前月份

- 今日格永远只显示 `今日进行中`。
- 已结束的完整周显示永久周梁。
- 包含今日的当前周显示本周暂梁，只统计到昨天，并显示覆盖天数，例如 `截至昨日 · 4/7 日`。
- 月标题区显示本月暂梁，只统计到昨天，例如 `截至昨日 · 16/31 日`。

### 4.3 历史月份

- 全部日梁均为已封存状态。
- 已结束周使用永久周梁档案。
- 月标题区使用永久月梁档案。
- 跨月周仍按周一至周日形成唯一 `week_id`；月梁只纳入业务日期属于该自然月的日梁。

### 4.4 详情与可访问性

- 日格默认只显示日期、头像与称呼，避免 6 位小数挤满月历。
- Hover / 键盘聚焦显示：梁位 6 位小数、夯/拉票数、三界香火、梁案数量、是否暂梁。
- 点击日梁可展开该日梁案标题列表；周梁/月梁显示覆盖日期与每日明细。
- `今日进行中`、`本周暂梁`、`本月暂梁`、`无存档` 必须有独立文本和 aria-label，不能只靠颜色区分。
- 支持 Escape 关闭、焦点约束、focus-visible、缩放、暗色主题与 `prefers-reduced-motion`。

## 5. 入口

建议在 Region 4 右侧礼仪控制列中，将四字入口放在 `上达天听` 下方：

```text
上达天听
进入梁祠
```

- 可见文案：`进入梁祠`。
- Hover / Focus：`查看日梁、周梁与月梁`。
- 它是只读历史入口，不是投票选项，不是第五个业务区域。
- 实施前应同步修订 `AGENTS.md` 与 `docs/020-ui-v0.1.md` 的冻结 Region 4 结构；在契约修订完成前，不应直接修改 UI。

## 6. 永久档案模型

秒级 `public_liang_snapshot` 继续保持有界，只服务今日近实时体验；梁祠使用独立的低频档案，不保留无限秒级快照。

建议的不可变记录：

```text
LiangDayArchive
  business_date              // PK
  up_votes
  down_votes
  total_incense
  case_count
  aggregation_policy_version
  finalized_at

LiangWeekArchive
  week_id                    // ISO week-year + week，PK
  period_start               // Monday
  period_end                 // Sunday
  up_votes
  down_votes
  total_incense
  covered_days
  aggregation_policy_version
  finalized_at

LiangMonthArchive
  month_id                   // YYYY-MM，PK
  period_start
  period_end
  up_votes
  down_votes
  total_incense
  covered_days
  aggregation_policy_version
  finalized_at
```

比例和梁子状态不必作为第二真相源入库；由原始计数与记录上的策略版本派生。

### 6.1 日切封存事务

下一业务日首次触发日切时：

1. 合并并封存昨日所有梁案为一个 `LiangDayArchive`。
2. 若昨日是周日，用七个已封存日梁生成上周永久周梁。
3. 若昨日是月末，用该自然月已封存日梁生成上月永久月梁。
4. 开启今日梁案与零票今日快照。
5. 增加单调 `archive_version`。

日、周、月归档应在同一服务器业务日期语义下幂等执行：相同日、周、月重复触发只能得到同一永久记录，不可重复插入或重复累计。

## 7. 一次历史获取，后续只更新今日

不要把历史数组加入现有完整 SSE state 帧，否则每次今日 revision 都会重复发送全部历史。

建议拆分：

```text
首次连接：
Backend GET /v1/history
  -> Host 缓存
  -> Browser GET /liangbiao/api/history
  -> 一次取得日 / 周 / 月永久档案

日常运行：
Backend GET /v1/snapshot
  -> 只返回今日 active case + 今日 global snapshot
  -> Host SSE 仍只推今日状态

业务日切：
Host 发现 business_date / archive_version 变化
  -> GET /v1/history?after_version=N
  -> 只补昨天及刚固定的周梁/月梁
```

当前周暂梁和当前月暂梁直接使用已获取的日梁档案，在 Host / Client 共享纯逻辑中派生；由于不含今日，它们在同一业务日内不会变化，不需要随 1 秒快照刷新。

历史读取建议支持：

- `archive_version` 与增量游标。
- `ETag / If-None-Match`。
- gzip / brotli 压缩。
- Host 缓存；浏览器标签只从本机 Host 读取，不让每个标签直接打社区后端。
- 历史请求失败时显示最后一次成功档案并标记 `档案未更新`；不影响今日投票。

## 8. GitHub Pages 定位

GitHub Pages 只作为未来可分享的公开静态镜像，不替代插件内梁祠。

- 日切封存后，可以按天触发一次静态档案构建。
- 不应按今日每票或 1 秒快照触发 Pages 部署。
- Pages 若展示今日数据，只能通过额外公共 API 拉取；这不是 Pages 自身的动态推送能力。
- 插件梁祠与 Pages 必须消费同一档案契约和同一聚合策略版本。
- 社区口令、Host 私钥或任何凭据不得进入 Pages JavaScript。

## 9. Cursor 实施顺序

1. 先修订产品契约：梁祠入口、今日进行中、暂梁截至昨日、周/月封存时机。
2. 增加纯领域聚合：日合并、周/月加权、周/月边界、零票与无档案语义。
3. 增加幂等日切归档与 `archive_version`。
4. 增加独立历史 API、Host 缓存和增量同步；保持今日 SSE 不携带历史。
5. 实现梁祠浮层、三层图标、详情与无障碍。
6. 最后再评估 GitHub Pages 静态镜像，不将其与核心梁祠绑成同一发布阻塞项。

## 10. 必测场景

- 今日格始终为 `今日进行中`，今日实时投票不会改变该图标。
- 本周暂梁、本月暂梁只统计到昨天；今日投票不会改变二者。
- 周一显示 `本周待积`；月初 1 日显示 `本月待积`。
- 日切只封存昨日一次；重复触发幂等。
- 周切只在完整周结束后生成永久周梁。
- 月切只在完整月结束后生成永久月梁。
- 同日多梁案正确合并为一个日梁。
- 跨月周按周一至周日聚合；月梁只统计本月日期。
- 零票日、无存档、未来日期三种状态互不混淆。
- 周梁/月梁按票数加权，不平均梁子枚举。
- 梁位与梁子状态来自同一周期计数和策略版本。
- 首次连接获取完整历史；今日 SSE 帧不携带历史数组。
- 日切后只获取归档增量，不重复发送全部历史。
- 历史服务失败不影响今日梁案、香火或投票。

## 11. 最终设计决策

> 梁祠以插件内独立月历浮层为主。今日只显示“今日进行中”，不形成日梁，也不参与本周、本月计算；本周暂梁和本月暂梁始终只统计截至昨天的已封存日梁，当天内保持不变且不入永久档案。下一周或下一月开始时，服务器将已经固定的完整周期幂等封存为永久周梁/月梁。历史首次连接一次获取，之后日常通道只更新今日，日切仅补新增档案。
