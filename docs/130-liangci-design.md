# 130 — 梁祠（日梁 / 周梁 / 月梁）设计方案

> 状态：**已于 v0.4.0 实现**。本文既是产品契约，也是实现验收基线。
>
> 本方案延续 `AGENTS.md` 的二元投票、梁位、梁子五态、业务日、快照一致性与软信任边界。
> 梁祠只读，不改变今日梁案、个人香火、投票资格或权威账本。

实现落点：

- 领域归档与暂梁派生：`src/domain/archive.ts`
- 严格历史 wire：`src/shared/history-v1.ts`
- SQLite v4 归档表与幂等封存：`src/backend/schema.ts`、`src/backend/service.ts`
- 独立后端/Host 历史路由：`GET /v1/history`、`GET /liangbiao/api/history`
- 浏览器冷数据缓存：`src/client/live-store.ts`
- 月历浮层与三层图标：`src/client/LiangciModal.tsx`、`src/client/LiangciIcon.tsx`

社区 staging 是否可用取决于后端是否已通过 `scripts/deploy.sh` 部署到包含
SQLite v4 与 `/v1/history` 的版本；客户端在旧后端上会诚实显示 `档案未更新`，
而今日梁案与投票照常工作。

## 1. 产品目标

梁祠是梁标的历史日历：以月历为主视图，用三种时间层级组织全局梁位。

- **日梁**：一个业务日一个日历图标。
- **周梁**：周一至周日七个日梁的汇总，显示在对应七天右侧。
- **月梁**：一个自然月全部日梁的汇总，显示在月份标题区。
- **今日**：尚未结束，不显示今日梁位或今日梁子终态，只显示专用的 **今日进行中** 图标。

梁祠的核心原则是：**只有已经结束的业务日才能进入历史计算。**

## 2. 冻结与临时结果

### 2.1 日梁

- 今日格固定显示 `今日进行中` 图标，不用实时今日梁位生成日梁图标。
- 今日不参与本周暂梁、本月暂梁计算。
- 到下一业务日开始时，服务器封存昨日的最终夯票、拉票与日梁元数据。
- 封存后的日梁不可被今日快照或浏览器时钟改写。
- 同一业务日若因运营归档、重开而存在多个梁案，当日日梁合并该业务日所有已关闭梁案的 accepted 夯/拉票数。

### 2.2 当前周梁

- 周期固定为服务器业务时区下的 **周一至周日**。
- 本周尚未结束时，显示 `本周暂梁`。
- 本周暂梁只使用本周一至昨天的已封存日梁；不包含今日。
- 暂梁不写永久档案，可由一次性历史数据在 Host / Client 侧即时派生。
- 下一周首个业务日到来时，上周结果已经固定，服务器生成且只生成一次永久周梁档案。
- 若今天是周一，本周没有任何已结束日期，显示 `本周待积`，梁位为 `--`，不可显示假 50%。

### 2.3 当前月梁

- 月周期按服务器业务时区下的自然月计算。
- 本月尚未结束时，显示 `本月暂梁`。
- 本月暂梁只使用本月 1 日至昨天的已封存日梁；不包含今日。
- 暂梁不写永久档案，可由一次性历史数据在 Host / Client 侧即时派生。
- 下一月首个业务日到来时，上月结果已经固定，服务器生成且只生成一次永久月梁档案。
- 若今天是当月 1 日，本月没有任何已结束日期，显示 `本月待积`，梁位为 `--`。

### 2.4 结果状态矩阵

| 对象 | 数据范围 | 展示状态 | 是否永久入档 |
|---|---|---|---|
| 今日 | 当前业务日 | 今日进行中 | 否 |
| 昨日及更早的日梁 | 完整业务日 | 已封存 | 是 |
| 当前周 | 本周一至昨天 | 本周暂梁 / 本周待积 | 否 |
| 已结束周 | 完整周一至周日 | 已封存周梁 | 是 |
| 当前月 | 本月 1 日至昨天 | 本月暂梁 / 本月待积 | 否 |
| 已结束月 | 完整自然月 | 已封存月梁 | 是 |

## 3. 聚合口径

主梁位采用“先汇总票数，再计算比例”，即按香火数加权：

```text
period_up_votes   = sum(day.up_votes)
period_down_votes = sum(day.down_votes)
period_total      = period_up_votes + period_down_votes

if period_total == 0:
    up_ratio = null
    down_ratio = null
    liangzi_state = WAITING
else:
    up_ratio = period_up_votes / period_total
    down_ratio = period_down_votes / period_total
    liangzi_state = liangziPolicy(up_ratio)
```

这等价于以每日总香火为权重，对日梁位做加权平均，并保持 `1 accepted vote = 1 incense` 的产品语义。

规则：

- 不平均 `梁工 / 梁总 / 梁神 / 梁圣 / 梁祖` 枚举。
- 零票日是合法的 `待开梁` 日梁；它在周期聚合中的票数权重自然为零。
- 功能上线前没有数据的日期显示 `无存档`，不可冒充零票日。
- 未来日期留空。
- 周梁/月梁的梁位、称呼与梁子图像必须来自同一组周期计数和同一聚合版本。
- 梁位显示继续截断而非四舍五入；详细卡保留 6 位小数。

若未来需要“典型的一天”视角，可在详情中增加次要指标 `有票日日均梁位`；它不得驱动主周梁/月梁图标或称呼。

## 4. 日历信息架构

梁祠使用居中的独立大型浮层，不采用侧抽屉，也不把 312px 的今日梁案面板扩展成月历。日历是稳定的二维信息结构，居中浮层比窄抽屉更易保持七日列、周梁列和月梁锚点的秩序。

```text
┌────────────────────────── 梁祠 ──────────────────────────┐
│ 梁祠       〈        2026 年 8 月        〉  本月暂梁   × │
│                                          截至昨日        │
│ 一    二    三    四    五    六    日       周梁         │
│ 日梁  日梁  日梁  日梁  日梁  日梁  日梁     已封存周梁   │
│ 日梁  日梁  日梁  日梁  日梁  今日进行中     本周暂梁     │
│ 选中日梁详情：梁位 / 夯拉票数 / 香火 / 梁案标题           │
└──────────────────────────────────────────────────────────┘
```

### 4.1 图标语言

- **日梁**：单页日历框 + 日期 + 小型梁子头像。
- **今日进行中**：未盖印的今日历页，明确写 `今日进行中`；它不是 `WAITING / 待开梁`，也不绑定实时今日梁子状态。
- **周梁**：七格日历册或横向卷轴框 + 周梁子头像。
- **月梁**：完整月历牌匾 + 较大的月梁子头像。
- **暂梁**：虚线或未盖印边框，并带 `暂` 标记和 `截至昨日` 文案。
- **永久档案**：实线封边或盖印视觉，不再出现 `暂` 标记。

日、周、月通过不同的“时间容器”区分；容器内梁子仍只使用 `待开梁` 和现有五态，不创造新档位。

### 4.2 当前月份

- 今日格永远只显示 `今日进行中`。
- 已结束的完整周显示永久周梁。
- 包含今日的当前周显示本周暂梁，只统计到昨天，并显示覆盖天数，例如 `截至昨日 · 4/7 日`。
- 月标题区显示本月暂梁，只统计到昨天，例如 `截至昨日 · 16/31 日`。

### 4.3 历史月份

- 全部日梁均为已封存状态。
- 已结束周使用永久周梁档案。
- 月标题区使用永久月梁档案。
- 跨月周仍按周一至周日形成唯一 `week_id`；月梁只纳入业务日期属于该自然月的日梁。

### 4.4 详情与可访问性

- 日格默认只显示日期、头像与称呼，避免 6 位小数挤满月历。
- Hover / 键盘聚焦显示：梁位 6 位小数、夯/拉票数、三界香火、梁案数量、是否暂梁。
- 点击日梁可展开该日梁案标题列表；周梁/月梁显示覆盖日期与每日明细。
- 详情使用浮层底部固定详情栏，不为每一天再打开第二层弹窗；选择不同日期时只替换详情内容。
- `今日进行中`、`本周暂梁`、`本月暂梁`、`无存档` 必须有独立文本和 aria-label，不能只靠颜色区分。
- 支持 Escape 关闭、焦点约束、focus-visible、缩放、暗色主题与 `prefers-reduced-motion`。

## 5. 美术与视觉系统

### 5.1 总方向

梁祠的视觉定义是：**现代编年志 × 克制梁祠**。

> 像 DSH 原生界面里长出了一座小型数字梁祠，而不是突然进入一款古风手游。

视觉占比：

- 80% DSH 原生桌面界面：语义色、字体、边框、圆角、密度、暗色模式。
- 15% 日历与编年档案感：日期页、七日册、月历匾、封存层级。
- 5% 梁祠符号：朱印、香火暖色、极简屋檐线；只做点睛。

Cursor 不拥有二次美术设计权。实现必须以本文与以下视觉母版为准：

- [`docs/assets/liangci-visual-spec.png`](assets/liangci-visual-spec.png)：整页布局、密度、色彩面积与层级。
- [`docs/assets/liangci-visual-spec.svg`](assets/liangci-visual-spec.svg)：可量取尺寸的矢量源稿。
- [`docs/assets/liangci-icon-system.png`](assets/liangci-icon-system.png)：八种关键图标/状态。
- [`docs/assets/liangci-icon-system.svg`](assets/liangci-icon-system.svg)：图标系统矢量源稿。
- [`docs/131-liangci-cursor-prompt.md`](131-liangci-cursor-prompt.md)：可直接交给 Cursor 的完整实施提示词。

若代码条件不能准确复现，应报告差异；不得自行替换成 Dashboard 卡片、古风游戏 UI、玻璃拟态或另一套头像。

### 5.2 大型浮层尺寸

- 目标宽度：`880px`；允许区间 `860–900px`。
- 最大高度：`min(760px, 86vh)`；内容超出时只滚动日历主体/详情，不让标题栏离开视口。
- 外圆角：`12px`；外边框 `1px solid color.border`。
- 内边距：`24px`；基础间距使用 8px 网格。
- 阴影：与现有 Panel 同源，仅一层外阴影，不叠多层暖色光晕。
- 日历主体：七个等宽日期列 + 一个 `124–136px` 周梁列。
- 日期格建议高度 `84px`；格间距 `8px`；日期格圆角 `8px`。
- 日历格不使用常驻外阴影；选中态用内描边或品牌色边框。

### 5.3 图标轮廓

三种时间层级不能只是同一头像按比例缩放：

- **日梁 / 单页日历**：左上日期、中央约 40px 梁子头像、底部称呼；适合快速扫描。
- **周梁 / 七日册**：顶部周序号、边缘七道细刻度、中央较大头像、底部称呼；暂梁附空心 `暂` 印，永久记录附小型实心 `封` 印。
- **月梁 / 月历匾**：横向小牌匾，月份与状态在左、52–60px 头像在右；不得做巨大宫殿匾额或浮雕金字。
- **今日进行中 / 未盖印日历页**：与日梁同家族，中央为大号 `今`，下方为 `进行中`，品牌蓝描边，右上留出未盖印位置；不显示任何实时梁子头像。

完整语法：

```text
品牌蓝“今”页       = 今日进行中
头像日历页          = 已封存日梁
空心“暂”印          = 当前周 / 当前月临时结果
实心“封”印          = 永久周梁 / 永久月梁
灰色空白页          = 无存档
待开梁头像日历页    = 有档案但零票
```

### 5.4 色彩

全部基础颜色继续来自 `src/client/theme.ts`：

- 浮层：`color.bgLayer`。
- 日期格/弱分区：`color.bgSubtle`。
- 正文：`color.textPrimary`。
- 次要信息：`color.textSecondary / textTertiary`。
- 今日进行中：`color.brand`。
- 暂梁提示与香火点睛：`color.warn`。
- 封存朱印：仅小面积使用现有朱红语义色，不把朱红铺成背景。
- 夯/拉不在月历里形成红绿对抗；主梁位与梁子状态才是结论。

单屏暖橙与朱红的合计面积应控制在约 8% 以内。它们是印记，不是主题背景。

### 5.5 字体与信息密度

- 只使用现有系统字体栈；不引入书法字体或额外字体依赖。
- `梁祠`：18–20px / 700。
- 月份导航：16px / 650，数字使用 tabular nums。
- 星期栏：11px / 600 / 次要文字色。
- 日期：11px / 650。
- 日梁称呼：11px / 650；默认格不放 6 位百分比。
- 周梁/月梁主称呼：12–13px / 700。
- 六位梁位、票数和标题只进入 Hover/Focus 提示或底部详情栏。

### 5.6 动效

只允许：

1. 打开梁祠：`120–160ms` 淡入 + 2px 上移。
2. 切换月份：`≤150ms` 的轻微水平过渡。
3. 选择日梁：边框与底部详情内容过渡。
4. 今日图标首次出现可播放一次极短的描边动画，随后静止。

禁止头像持续漂浮、印章循环闪烁、日期依次弹入、整页香火粒子、Hover 大幅缩放或多层发光。梁祠是查阅档案的空间，动效必须比今日梁案安静。

### 5.7 明确禁止的美术做法

- 大面积金红、宫殿背景、龙纹、牌位阵列。
- 羊皮纸、木纹、卷轴纹理铺满页面。
- 玻璃拟态、霓虹、赛博光效和多层彩色阴影。
- emoji 充当日梁/周梁/月梁图标。
- 为梁祠重新生成另一套梁子头像。
- 每个状态使用不同卡片底色，造成彩色棋盘。
- 用红绿单独表达夯/拉，或只靠颜色表达暂梁/封存/无档案。
- 为“今日进行中”使用 spinner；它不是加载中。

## 6. 入口

建议在 Region 4 右侧礼仪控制列中，将四字入口放在 `上达天听` 下方：

```text
上达天听
进入梁祠
```

- 可见文案：`进入梁祠`。
- Hover / Focus：`查看日梁、周梁与月梁`。
- 使用“极简屋檐 + 日历页”的单色 `currentColor` SVG；不得用寺庙剪影、香炉或 emoji。
- `上达天听` 与 `进入梁祠` 使用相同字级和点击高度，中间仅一道短分隔线；默认为次要文字色，Hover/Focus 才进入品牌色。
- 它是只读历史入口，不是投票选项，不是第五个业务区域。
- 实施前应同步修订 `AGENTS.md` 与 `docs/020-ui-v0.1.md` 的冻结 Region 4 结构；在契约修订完成前，不应直接修改 UI。

## 7. 永久档案模型

秒级 `public_liang_snapshot` 继续保持有界，只服务今日近实时体验；梁祠使用独立的低频档案，不保留无限秒级快照。

建议的不可变记录：

```text
LiangDayArchive
  business_date              // PK
  up_votes
  down_votes
  total_incense
  case_count
  aggregation_policy_version
  finalized_at

LiangWeekArchive
  week_id                    // ISO week-year + week，PK
  period_start               // Monday
  period_end                 // Sunday
  up_votes
  down_votes
  total_incense
  covered_days
  aggregation_policy_version
  finalized_at

LiangMonthArchive
  month_id                   // YYYY-MM，PK
  period_start
  period_end
  up_votes
  down_votes
  total_incense
  covered_days
  aggregation_policy_version
  finalized_at
```

比例和梁子状态不必作为第二真相源入库；由原始计数与记录上的策略版本派生。

### 7.1 日切封存事务

下一业务日首次触发日切时：

1. 合并并封存昨日所有梁案为一个 `LiangDayArchive`。
2. 若昨日是周日，用七个已封存日梁生成上周永久周梁。
3. 若昨日是月末，用该自然月已封存日梁生成上月永久月梁。
4. 开启今日梁案与零票今日快照。
5. 增加单调 `archive_version`。

日、周、月归档应在同一服务器业务日期语义下幂等执行：相同日、周、月重复触发只能得到同一永久记录，不可重复插入或重复累计。

## 8. 一次历史获取，后续只更新今日

不要把历史数组加入现有完整 SSE state 帧，否则每次今日 revision 都会重复发送全部历史。

建议拆分：

```text
首次连接：
Backend GET /v1/history
  -> Host 缓存
  -> Browser GET /liangbiao/api/history
  -> 一次取得日 / 周 / 月永久档案

日常运行：
Backend GET /v1/snapshot
  -> 只返回今日 active case + 今日 global snapshot
  -> Host SSE 仍只推今日状态

业务日切：
Host 发现 business_date / archive_version 变化
  -> GET /v1/history?after_version=N
  -> 只补昨天及刚固定的周梁/月梁
```

当前周暂梁和当前月暂梁直接使用已获取的日梁档案，在 Host / Client 共享纯逻辑中派生；由于不含今日，它们在同一业务日内不会变化，不需要随 1 秒快照刷新。

历史读取建议支持：

- `archive_version` 与增量游标。
- `ETag / If-None-Match`。
- gzip / brotli 压缩。
- Host 缓存；浏览器标签只从本机 Host 读取，不让每个标签直接打社区后端。
- 历史请求失败时显示最后一次成功档案并标记 `档案未更新`；不影响今日投票。

## 9. 本阶段范围

本阶段只实现插件内梁祠。明确不做：

- GitHub Pages。
- 公开梁祠网站或落地页。
- Pages 构建/部署 workflow。
- 为网页开放的额外 CORS、SSE、WebSocket 或鉴权方案。

## 10. 已完成的实施顺序

1. 先修订产品契约：梁祠入口、今日进行中、暂梁截至昨日、周/月封存时机。
2. 增加纯领域聚合：日合并、周/月加权、周/月边界、零票与无档案语义。
3. 增加幂等日切归档与 `archive_version`。
4. 增加独立历史 API、Host 缓存和增量同步；保持今日 SSE 不携带历史。
5. 按视觉规范实现梁祠浮层、三层图标、底部详情栏与无障碍；复用现有头像和主题 token。

## 11. 必测场景

- 今日格始终为 `今日进行中`，今日实时投票不会改变该图标。
- 本周暂梁、本月暂梁只统计到昨天；今日投票不会改变二者。
- 周一显示 `本周待积`；月初 1 日显示 `本月待积`。
- 日切只封存昨日一次；重复触发幂等。
- 周切只在完整周结束后生成永久周梁。
- 月切只在完整月结束后生成永久月梁。
- 同日多梁案正确合并为一个日梁。
- 跨月周按周一至周日聚合；月梁只统计本月日期。
- 零票日、无存档、未来日期三种状态互不混淆。
- 周梁/月梁按票数加权，不平均梁子枚举。
- 梁位与梁子状态来自同一周期计数和策略版本。
- 首次连接获取完整历史；今日 SSE 帧不携带历史数组。
- 日切后只获取归档增量，不重复发送全部历史。
- 历史服务失败不影响今日梁案、香火或投票。
- Light/Dark 下不出现硬编码白底、黑字或低对比印章。
- 125%/150% zoom 下七日列与周梁列不互相覆盖；必要时浮层主体横向滚动，不压缩到不可读。
- 实现与视觉规范的外框、列宽、密度、图标轮廓和色彩角色一致，不退化为通用 Dashboard。

## 12. 最终设计决策

> 梁祠以插件内居中大型月历浮层为唯一当前方案，视觉采用“现代编年志 × 克制梁祠”。今日只显示“今日进行中”，不形成日梁，也不参与本周、本月计算；本周暂梁和本月暂梁始终只统计截至昨天的已封存日梁，当天内保持不变且不入永久档案。下一周或下一月开始时，服务器将已经固定的完整周期幂等封存为永久周梁/月梁。历史首次连接一次获取，之后日常通道只更新今日，日切仅补新增档案。GitHub Pages 完全退出本阶段范围。
