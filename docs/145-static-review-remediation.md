# 145 — 0.8.1-beta.0 静态复核整改与剩余风险

> 日期：2026-08-18。对象：`0.8.0` 静态评审之后的修复候选
> `0.8.1-beta.0`。本报告区分“已修复”“有意保留的取舍”和“外部阻塞”，
> 不把社区 soft-trust 包装成可信公投。

## 已修复

1. Caddy 反代来源：后端仅在 socket 来源为回环时信任有效、单值
   `X-Forwarded-For`；公网直连伪造头无效。真实 MacBook 签名 bootstrap 后，
   journal 已记录非回环来源地址。
2. 入梁券竞态：Host 遍历公开响应的完整券列表；整页在并发中耗尽时最多刷新
   两次，避免库存仍足却只试前 5 张或前 20 张。
3. 正式准入：旧共享口令从 Host、后端、CLI、安装脚本和环境模板中删除；部署
   时静默清除服务器旧变量，首次登记只走入梁券。`ALLOW_UNSIGNED=1` 只能绑定回环。
4. 错误语义：确定性 4xx 读取不再重试；投票 429 使用
   `vote_rate_limited`，通过 Host 保持 429，且不把 authority 误判为离线。
5. 身份 miss 限流：未登记 rekey/revoke 先进入有界 miss 桶，再返回 401，文档所述
   30 分钟扫钥窗口实际生效。
6. 本地玩法：删除旧浏览器 authority 偏好自动切换；显式 POST 必须是空 JSON 且
   带同源自定义动作头，普通跨站表单不能切换整台 Host。
7. 梁祠：桌面 6 周月份在一屏显示，31 日、周梁、月梁详情完整；窄屏只横向滚动，
   日梁/周梁称谓均无裁切或纵向溢出。
8. 下一炷水合：跨整炷边界的首次权威水位直接对齐，不再沿取模轨迹播放百万级
   跳动；外推永不越过下一炷权威边界。
9. 一键更新：tarball 先进入内容哈希缓存，修复 DSH 对同路径/同版本重构包错误
   返回 “Already up to date”；更新前后用户 storage 摘要保持一致。
10. 发布版本：npm `0.8.0` 已不可变，修复源码提升为 `0.8.1-beta.0`，杜绝
    “同一版本号、两套字节”。本轮不执行 npm publish。

## 仍有影响的风险

1. **Token 不可验证（结构性 P0）**：Host 可谎报 Token；不能宣传实名、一人一票、
   核验用量或反女巫。修复必须依赖未来 DSH 可验证身份/用量证明，不是本仓能补。
2. **公开券可被慢速扫库存**：公开 secret 是一键领券的产品取舍。全局默认
   120 次/分钟只保护服务器负载，不保护库存真实性；生产当前 1,000 张 active
   券、99,991 次剩余认领，仍须监看 `liang tickets status`、告警和应急停发。
3. **业务端点未做生产 1K 写压**：健康端点 1K TLS 峰值通过；`/snapshot` 在日切
   可能幂等写库，投票会永久改变梁位，所以本轮没有在生产账本重复施加 1K 业务压测。
   隔离库已覆盖并发事务；正式容量结论还需独立压测环境。
4. **GET 日切副作用（有意保留）**：`/snapshot` 与 `/history` 作为惰性日切触发器
   调用 `ensureActiveCase()`。它保证午夜无空窗，但不满足“GET 永远无写”的纯 REST 语义。
5. **Mac mini 未补验**：`192.0.2.86:22` 当前连接超时。MacBook 和全新隔离
   profile 已通过，但独立第二台实机仍需设备恢复可达后运行同一候选包。
6. **本机 Node 偏低**：MacBook 为 v22.17.0，低于 engines 的 22.19；全部测试通过，
   生产为 v22.23.1。正式用户仍必须使用 `^22.19.0 || >=24`。
7. **DSH RC 依赖漂移**：rc.6 profile 会解析到部分 rc.7 包并产生 peer warning；
   实机和干净安装通过，但升级 DSH 前仍须重跑兼容矩阵。
8. **视觉/a11y 自动化不完整**：本轮 Chromium 实测桌面 1280×720 与窄屏
   390×844；没有 axe 和截图差异流水线，浏览器运行时也无法模拟低于 720px 的高度。

结论：社区 soft-trust 候选可部署测试；仍不满足 verified production 的信任门槛。
