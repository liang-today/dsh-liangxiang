# 钱包启用、旧版兼容与过期规则验收

状态：2.0.0-alpha.3源码候选，未发布、未部署生产；本次只使用独立SQLite、环回HTTP和临时DSH Profile。原生产、原备份及人工测试环境未修改。

## 最终行为

- 尚未使用累计协议的身份保持旧日账。业务换日清除可用余香及不足一炷进度，历史申报、投票及档案保留；离线和重启也不会把过期香火复活。
- 首次新版累计协议请求只承接当天实际余香和进度，赠香凭证及申报水位不变；不加总历史日账。启用点持久化，不可由旧请求关闭。
- 已启用身份的旧个人请求在修改账本前返回412及最低版本2.0.0，不领取新赠香、不更改申报、不动可用/冻结/仓位；市场按原时点独立结算。
- 市场和云流接口也要求累计协议，防止未声明能力的探测请求暗中启用钱包；认证和资金事务不因能力头而放宽。
- schema15保留原schema12–14候选钱包已存在的资产与冻结。正式schema10日账没有这些钱包，使用逐身份首次启用规则。

## 已发布旧二进制的边界

正式1.2.0会丢弃服务端错误说明。服务端返回中文和最低版本，不能远程改变其Host/浏览器代码。
因此已经安装的原始1.2.0仍可能只显示HTTP412；安装旧版提示补丁或2.0后才有明确文字。
本次未声称已让所有旧安装自动获得提示，也没有通过虚构日账、清空钱包或释放冻结来伪装兼容。

旧版提示补丁基于正式v1.2.0，仅增加错误识别与展示，不加入钱包/梁股。实际是否发行此维护包需单独决定；直接升级2.0也能继续原身份。

## 发布与迁移边界

修复须集成到最终2.0候选后再走正式发布门禁。生产源核对为既有schema10，迁移到15；旧主服保留转发和回退。正式接管与备份恢复验收后，按精确清单清理新ECS内测数据、服务、客户端及测试入口；原轻量测试机和原备份保留。方案见[切换计划](RELEASE_2_CUTOVER_PLAN.md)。
