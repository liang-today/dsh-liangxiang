## 用户行为

- 默认关闭。梁相案牍保留 2×2 主工具格；整格点击“定时上香”切换已开启/已关闭，保存期间显示“保存中”。10 分钟节奏、23:59 收尾与默认方向用短句放在悬停/键盘聚焦提示内，自然换行，不占常驻空间。
- 旧版已开启的日终设置迁移为关闭，保留默认方向和已有票据；需在同一个开关重新开启一次，才授权白天也自动上香。新版设置保存内部 `cadenceVersion: 1` 标记，不增加用户配置项。
- 右键夯或拉只保存默认方向，在原反馈行显示“定时上香：默认投夯/拉”；键盘菜单键或
  Shift+F10 同样可设置。设置方向不投票、不自动开启开关。
- 核对香火仍有修复作用：丢弃未确认的本地观察后重新读服务端账本。保留它的
  确认流程，收进“显示异常？”折叠入口；日常观察、声明、刷新与重连继续自动执行。
- DSH 必须运行并加载该 Profile；浏览器可以关闭。关闭 DSH、睡眠、断网或额度
  不足时不保证完成，午夜后不补投昨天的余额。

## 最小执行模型

复用原开关，不新增定时设置、频率选择、策略方向或逐炷队列。默认节奏由现有
单次上限 / 每分钟恢复速率导出，目前为 500 / 50 = 10 分钟，不新增 env 配置。

- 白天：权威余额达到 500 炷后，等待 10 分钟尝试一笔 `count=500` 的普通倾炉。
  读账后不足 500 炷就保留尾数；后续重新达到门槛时重新等待。完成后若仍满额，再等
  10 分钟。不因普通状态帧重置计时，不以 HTTP 轮询探测门槛。
- 23:59：额外尝试一笔 `min(remaining, VOTE_COUNT_MAX)` 收尾，少于 500 炷也可投。
  若有本日未确认的周期意图，先沿用原 ID 确认结果，再建立收尾意图；收尾完成后不再追投。
- 两者都由既有权威预算决定实际接受量；首次预算或手动消耗可能使接受量小于申请值。
  不估算或放宽服务端额度，不宣传能清空任意余额。DSH 停止、睡眠或断网期间不会补跑
  周期；重启后新周期重新等待 10 分钟，已持久化的未确认意图仍按原票据重试。

Host 使用一个可取消的定时器，白天和收尾共用原串行执行器与一笔持久化意图。
每个模式只保存最近一笔，`kind=periodic/closing` 区分用途；旧无 kind 的票据按
收尾处理。业务日、梁案、模式改变或关闭/重开后使旧定时器及异步准备失效；
刷新和落盘后都复核，旧任务不会消耗次日赠香。
在线时以 bootstrap/snapshot 的 `server_time` 校正 Host 时间，按后端下发的
`business_timezone` 找到下一业务日边界，支持 DST 的 23/25 小时日；不相信浏览器
日期。调度不依赖新增 Backend 字段，最终投票资格仍由后端决定。离线才使用显式本地时区。

手动与自动共享 Host 串行入口。长按开始时发送一个仅限 Host 的短暂操作标记，给尚未发出的手动请求留位；
取消/断开的标记最多 5 秒自然失效，不是投票或余额。已有手动请求先结束，随后
至少留 2 秒安静窗口；排队任务开始执行、异步读账和意图落盘后都重新检查，慢请求不会跳过等待。
自动在实际发出前再读账。自动准备过程中出现新的手动请求会先让位；已发送的
请求保持自己的归属，后续手动请求等待其权威结果。Backend 的事务扣香、余额、
限流、幂等和旧案拒绝保持最终权威，多标签页不能各自花一份余额。

每笔自动意图的业务日、梁案、方向、count、request ID 先写入 Host 持久化，再发出。
结果不确定、重启、偏好改变后的重试均保留原始 payload 和 ID，不生成新意图逃避
幂等。失败最多每 5 秒重试，结束前 5 秒不再启动新请求；已发送请求若跨日到达，
由 Backend 拒绝旧案。新日不重放旧意图。在线/离线分别保存最近一笔回执，空间有界。
模式切换中的请求暂停，排队请求不得改投另一模式。存储尚未就绪时不可开启。

设置与回执放在现有 Host `settings` 表的独立 `day_end` 行，沿用公开的
`storageDomain` 接口，不改 DSH core。校验仍接受旧配置；该行保留旧版设置校验
需要的 `authorityPreference` 字段，不改变实际模式行。wire 偏好仍为可选字段，
旧 Host 不提供时新客户端将该开关标为不可用；浏览器不保存权威设置或自动任务。

## 自动上香的本机统计

Host 按在线/离线分别保存自动上香的今日及累计夯/拉数量，与完成回执一起落盘；
只计实际成交量，不按申请数量或余额差值推测。状态帧提供固定大小的可选计数投影，
浏览器在展示时与原有手动记录相加，用于“此身香火”和梁小号，不写回浏览器手动账本。
因此无浏览器时仍记数，刷新、重连、多标签页不会重复累加；业务日改变仅清今日部分。
这些本机统计不上传社区，也不参与扣香、梁位或投票资格。

后端 v11 为新成交保存原始接受量，并通过可选的 `accepted_incense` 在幂等重放中返回；
`spent_incense` 仍为本次实际新增扣香量，重放保持 0。这使丢失回执或统计落盘失败后
可以按同一意图恢复一次统计。旧后端及旧回执缺少该字段时，只记录能确认的本次成交量，
不把申请值或其他手动支出算作自动成交，不倒推不可确认的历史记录。

## Issue #4

原 Host 在启动时固定本地 interval，忽略 bootstrap 的 `snapshot_refresh_seconds`，
后端调慢发布无法减少请求。现在 Host 订阅当前服务，仅当有效 cadence 改变时重建
唯一计时器；离线或没有可用 wire 的启动阶段使用本地 env；在线连接帧以默认 1 秒重连，
bootstrap 成功后采用后端值，切换模式与重新 bootstrap 后跟随新的权威值。
普通状态更新不重置等待，卸载移除订阅与计时器，值限制在既有 1–3600 秒范围内。

客户端继续使用 SSE；其 wire cadence 控制悬停刷新最短间隔（至少 2 秒），避免
悬停绕开后端减负。显式打开面板仍能立即刷新。保留 additive wire 契约，旧客户端
和旧 Host 的滚动升级路径不因删除字段而中断。
