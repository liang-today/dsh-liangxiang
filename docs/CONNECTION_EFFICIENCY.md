# 连接与消息开销

## 2.0.1 行情恢复修复候选（未发布）

2.0.0的Host在云端实时推送失效后会继续轮询公共快照，但未同步市场缓存，
因此主面板能跟随社区变化，梁股当前点和分钟K线却可能停在旧状态。
本轮让HTTP快照与云推送复用同一公共点位更新逻辑；分钟K线仍只读后端真实记录，
不会从两次快照补造开高低收或历史成交量。

仅在云流不健康、且本Host请求过市场后，复用现有单flight市场读取校准当前K线、
盘次与香池，间隔至少5秒且不短于后端快照cadence。正常云流不增加市场轮询，
多标签页不增加Host计时器。恢复读取不提交用量、上香或仓位意图，不自动重发待确认订单。
身份、业务日或案号变化使旧请求失效，卸载后不再推进状态。

浏览器市场首读或推送失败需有界重连，不能依赖原生EventSource对非200响应继续重试。
失败时标记暂未连接，保留最后确认的数据；恢复仅补读，不让过期响应回滚新状态。
回归入口：`host-market-recovery`、`host-market-recovery-route`及浏览器市场恢复检查。
本轮不部署正式后端，不回填首日缺失的历史分钟K线，也不修改正式账本。

## 1.3.0-alpha.6 通信候选

本轮不改变 wire 格式、行情 cadence、记账事务或安装身份的信任级别：

- 新建云订阅只发送本人的首帧，公共读集合在一秒内复用，不重新遍历所有旧连接。
- 正常广播每次最多处理64个连接，再让出事件循环；同一时刻最多一轮广播，避免积压。
- 公共市场、当前点和分钟烛线每轮读取一次。钱包仍按本人查询；仓位只在同一安装身份、同场且钱包版本不变时复用。缓存只在服务进程内，绝不作为扣款权威。
- 市场固定SQL使用最多128项的预编译缓存，不以身份、请求ID或历史长度扩张。
- 累计香火/累计香客仅为公共展示，每秒至多扫描一次；换案、清理和复位立即失效，不缓存私人余额或扣款资格。
- 复用最多2048个已解析的公钥对象，逐请求签名、时效和设备校验不变；同一请求复用刚读到的身份行，访问记录仍逐请求写入。精确相同时间戳的业务日期转换复用结果，不近似跨日边界。
- 普通请求只做一次完整签名校验。未知身份仍先验签后拒绝准入，不能借普通请求自动注册；已有身份仍检查设备绑定并更新访问记录。
- 慢连接的首次背压等待 `drain`，期间合并为最新状态；缓冲超过64KiB或持续阻塞25秒则断开。重连首帧、心跳、身份撤销与卸载清理保留。
- Host重连采用有上限的随机指数退避；只有收到有效帧并稳定30秒后才重置退避。取消旧流不等待可能卡住的网络清理承诺。
- 默认监听队列2048；后端HTTP空闲65秒、代理60秒，减少重复建连与复用已关闭连接。现有请求头截止时间保留。
- Caddy保留 `ProtectProc=invisible` 与 `ProtectKernelTunables=true`，但使用 `ProcSubset=all`，让Go读取内核 `somaxconn`；`pid` 会隐藏该路径，导致Go回退到128。安装此配置后需在维护窗口重启代理，再以实际监听队列核对；普通reload不会保证重建已有监听socket。下述容量与结算测试期间仍保留原代理配置；后续部署记录见本节末尾。

接口上香/仓位响应继续立即返回，公共状态仍每秒合并；历史与回执保持有界冷通道。不新增轮询、不引入新服务或数据库。

## 1.3 累计钱包候选

当前独立候选已增加 Linux Backend → 本机 Host 的认证 SSE。本机 Host 主动建立连接，服务器沿同一 HTTPS 响应流推送公共快照、阶段和本人的钱包变化；浏览器继续使用原有本机 SSE。

- 每 Host 只有一条云流，公共快照每秒最多生成一次后分发；相同内容不重复发送。
- 公共市场版本持久化，公共批次/池量共享缓存；稳定订阅不逐连接开启写事务。
- 私人钱包只推给本人。需要核对用量水位时补读个人账本，不从余额变化猜测声明到账。
- 声明响应不确定时先核对原累计水位，保留请求提交时的本地观察边界，避免重复凝香或吞掉在途新用量。
- 云流健康时低频校准；旧后台不支持或连接失效时，保留原 cadence 回退与有界重连。
- 25 秒心跳、连接数/缓冲上限和卸载清理均保留；历史 K 线与回执走分页冷通道。

候选的具体契约与验证见 [`MARKET_WALLET.md`](MARKET_WALLET.md)、[`MARKET_VALIDATION.md`](MARKET_VALIDATION.md)。以下是已发布 1.2 系列的轮询与本机 SSE 基线，不能用它推断候选仍每秒轮询。

## 本轮改进

Host 保持原有权威刷新节奏，只省去内容完全相同的 SSE 状态帧。
比较完整 wire 的全部字段，仅排除过程内递增的 `revision`；没有删减字段或改用差量协议。
每次新连接仍发送完整状态，25 秒心跳保留。

真实 HTTP/SSE 双标签页回归中，首次连接后连续触发 60 次内容相同的权威读取通知：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 每标签页完整状态帧 | 61 | 1 |
| 两标签页合计完整状态帧 | 122 | 2 |
| 权威读取通知 | 60 | 60 |
| 心跳、初次连接、重连完整状态 | 保留 | 保留 |

这是固定输入下的帧数回归，不代表线上流量的固定降幅。真正变化的每一帧仍立即发送：
香火余额与凝香进度、同版梁位、统计、广播发布和失效、日终偏好、档案游标、刷新节奏、
在线可用性、模式及 Host epoch。重连接受新 epoch 的低 revision，旧帧拦截规则不变。

## 保留的连接行为

- 每个 Host 一条权威快照计时器，采用后端 cadence；标签页数量不会增加该定时器。
  默认 1 秒一次快照，每 5 个 tick 补读个人账本，避免其他 Host 的余额变化长期不可见。
  默认稳定期约为每分钟 60 次快照和 12 次个人读取，启动、操作与失败重试另计。
- 每标签页初次读取状态与独立档案冷通道，再用一条 SSE 接收状态；没有浏览器后台轮询。
  档案后续仅按 `archive_version` 拉取增量，不塞进日常状态帧。
- 悬停刷新受 `max(2 秒, 后端 cadence)` 限制；显式打开立即刷新。
  并发 bootstrap、snapshot、history 已合并在各自现有入口，避免重复在途读取。
- Token 声明合并 1 秒内的连续结算，内容未增长时不提交；投票先冲刷尚未提交的声明。
  倾炉与日终上香复用一笔 `count` 意图，不按香火数量循环发请求。
- 日终关闭时没有排期请求；开启后日间只有 Host 定时器，浏览器可关闭。
  手动长按保护只在日终已开启时通知 Host，保留这一步以避免自动上香抢先。
- 断线保留最后状态与在线偏好，使用有界重连退避；不靠公共快照解除身份故障。
  卸载清理 SSE、心跳、计时器、订阅与可取消请求。

## 未采用的优化

不延长默认轮询、不停掉隐藏标签页状态、不删除个人账本补读，也不缓存或节流显式打开。
这些做法会改变投票反馈、广播失效、跨端余额或恢复时效。
不引入跨标签主从选举、SharedWorker 或服务器长连接改造；当前收益不足以抵消生命周期、
DSH 兼容和故障接管成本。服务器请求数量本轮不变。
